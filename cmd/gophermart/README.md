# Накопительная система лояльности «Гофермарт» (Исполняемый модуль)

Данная директория содержит точку входа (`main.go`) для сборки и запуска production-ready микросервиса накопительной системы бонусов. 

## 🏗 Сборка приложения

Для компиляции бинарного артефакта выполните команду из корневой директории проекта:
```bash
go build -o cmd/gophermart/gophermart cmd/gophermart/main.go
```

## ⚙️ Флаги запуска и Переменные окружения

Сервис поддерживает гибкую конфигурацию как через аргументы командной строки, так и через переменные среды (значения из флагов имеют высший приоритет):

| Флаг | Переменная окружения | Описание | Дефолтное значение |
| :--- | :--- | :--- | :--- |
| `-a` | `RUN_ADDRESS` | Адрес и порт запуска HTTP-сервера | `localhost:8080` |
| `-d` | `DATABASE_URI` | Строка подключения (DSN) к СУБД PostgreSQL | *обязательно* |
| `-r` | `ACCRUAL_SYSTEM_ADDRESS` | Адрес внешней системы расчета баллов лояльности | *обязательно* |

Пример запуска:
```bash
./gophermart -a :8081 -d "postgres://user:pass@localhost:5432/mart?sslmode=disable" -r "http://localhost:8080"
```

## 🚀 Архитектурные особенности Highload-контура

Перед запуском бинарного файла в эксплуатацию важно учитывать заложенные механизмы оптимизации производительности:
1. **Zero-Allocation HTTP-Слой:** Чтение входящих запросов и стриминг JSON-ответов оптимизированы через `sync.Pool` и кастомные I/O буферы для разгрузки системного сборщика мусора (GC).
2. **Синхронизация Облачного Деплоя:** На этапе холодного старта функция `RunMigrations` использует распределенный неблокирующий замок СУБД `pg_try_advisory_lock(1777)`. Это позволяет безопасно масштабировать сервис горизонтально (например, до 10+ подов в Kubernetes) без риска Connection Storm или порчи служебных таблиц миграций.
3. **Пул Финтех-Соединений:** Сервис автоматически поддерживает до 50 активных сессий с СУБД PostgreSQL, резервируя 10 «горячих» коннектов со старта для минимизации задержек на рукопожатие TCP Handshake.
4. **Отказоустойчивый Воркер:** Фоновый процесс асинхронно стягивает начисления по заказам через буферизированный канал на 1000 элементов, снабжен изоляцией паник (`recover()`) и деликатно реагирует на рейт-лимиты внешнего API (`Retry-After`), переводя горутину в управляемый сон.
